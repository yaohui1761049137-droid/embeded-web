# ADR-0002: 高强度密码策略与 3 个月有效期

- 日期:2026-08-11（移植到 main:2026-08-14）
- 状态:已接受
- 词汇:密码策略、密码有效期、强制改密、存量用户、踢会话（见 CONTEXT.md 词汇表）

## 背景

现状:`users` 表只有 `password_hash`,创建/重置密码仅校验长度(6-64 字符),无强度要求、无到期概念。root 通过 `user_create.cgi` / `user_passwd.cgi` 管理用户,系统没有任何"用户自己改密码"的入口。

需求:创建用户功能需支持高强度密码策略——10 个字符及以上、大小写字母/数字/特殊符号组合,且每次修改后有效期 3 个月。

## 决策

1. **适用范围**:策略适用于所有账号(含内置 root/admin),创建、root 重置、用户自改三种操作一律检查强度并重启计时。
2. **强度规则**(后端 C 为信任边界,前端 JS 仅做 UX 提示):
   - 长度 10-64 字符(上限沿用现有 64);
   - 四类字符**各至少 1 个**:大写字母 `[A-Z]`、小写字母 `[a-z]`、数字 `[0-9]`、ASCII 可见标点;
   - 中文、空格、控制字符一律拒绝;
   - 新密码不得与当前密码相同(哈希比对)。
3. **有效期**:每次修改(创建/重置/自改)后 90 天,起点记录在新增列 `password_changed_at`;到期前 7 天,登录成功时提示剩余天数。
4. **存量用户迁移**:策略上线时,库中已有用户的 `password_changed_at` 置 0,视为已过期 → **首次登录强制改密**,不要求旧密码满足策略。
5. **到期行为**:密码到期(或首次登录)时,登录成功但进入**强制改密**状态——除改密外所有 CGI 在请求门卫(gate 阶梯)中被拦截,直到改密成功。强制改密检查位于 gate 的会话校验之后,8 个受保护 CGI 无需各自实现;`user_change_pass.cgi` 使用豁免变体 `gate_json_session_no_policy`(会话 + CSRF 仍强制)。
6. **用户自改密**:新增独立页面(change.html)+ 新 CGI,要求输入并验证**当前密码**,通过后设置新密码、重置计时、踢掉该用户的其他活跃会话(仅保留当前会话)。
7. **审计**:创建/重置/自改均写入 `audit_log`(自改动作 `change_password`,重置沿用 `reset_password`)。
8. **db_init**:全新创建 root 时 `password_changed_at` 保持 0(列默认值)→ 首次登录强制改密(运维设置的密码可能为弱密码,不留后门);root 已存在时重跑 db_init 更新密码 → 重置计时。

## 理由

- 全账号统一强制,不留 root 弱密码后门;到期采用"强制改密"而非"禁止登录",避免 root 密码过期导致整个系统死锁(与登录后认证流程兼容)。
- 存量密码一律视为过期,策略上线即无漏洞,且不破坏现有登录凭据(仍可登录,只是先改密)。
- ASCII 标点集合定义清晰、跨端(C/Python 测试)一致;中文等非 ASCII 拒绝,避免全角/半角与编码歧义。
- 后端拦截是"强制"的语义保证:仅前端跳转可被直接调 CGI 绕过。
- 改密验证当前密码 + 踢其他会话,把会话劫持者借改密接管账号的窗口关掉。

## 后果

- **DB 迁移**:`users` 表新增 `password_changed_at INTEGER NOT NULL DEFAULT 0`;auth_init 以 PRAGMA table_info 探测,旧库自动 ALTER,存量行置 0;新建用户由 users_create 显式写当前时间(创建时密码已满足策略)。
- **auth.c**:新增密码策略校验函数、到期/强制改密状态查询、改密后踢会话的删除逻辑。
- **gate.c**:会话校验后增加强制改密检查(page 模式 302 到 change.html,JSON 模式输出"密码已过期,请先修改密码")。
- **login.cgi**:POST 成功但需强制改密时 302 到 change.html(否则 main.cgi);7 天预警通过主控页横幅展示。
- **新增**:`user_change_pass.cgi`、`www/change.html`;`user_create`/`user_passwd` 经 users 模块接入策略检查并写 `password_changed_at`。
- **测试**:test_gate.sh 与 test_suite.sh 增加策略用例(长度/四类/拒绝项/到期强制/踢会话)。
- **风险**:到期判定依赖板载时钟(无 RTC 电池则重启后时间错乱会误判到期)——文档明示,不为此引入 NTP 依赖。

## 备选方案(未采纳)

- **A. 到期禁止登录**:root 自己密码过期即锁死全系统,只能控制台 `db_init` 恢复。
- **B. 仅前端校验**:后端不拦,懂技术的用户可绕过直接调 CGI。
- **C. 密码历史表(最近 N 次禁复用)**:更严格但需新表与迁移,本期只做"与当前密码不同"。
- **D. 存量密码不迁移**:策略上线后弱密码仍长期有效,与需求目的相悖。
